# 参考项目与依据

资料查阅日期：2026-11-08。语言、框架和目录选择是本项目的设计建议；官方资料用于确认能力和限制，不代表已经完成集成或性能比较。

## 1. 本地 ShitBot 基线

参考仓库：[hutuyee/ShitBot](https://github.com/hutuyee/ShitBot)。本次阅读时 HEAD 为 `02983fc745e4a7e506835f9455085f5ae1ea2224`；这是代码分析基线，不包括本次随后对 README 的文字调整。

| 依据 | 提取出的约束 |
| --- | --- |
| `pom.xml`、`docs/development.md` | 现有 api / core / renderer / transports / platforms 模块划分，以及各平台不同 Java 目标 |
| `README.md`、`docs/commands.md`、`docs/configuration.md` | 普通版实际已有能力与面向服主的使用方式 |
| `docs/proxy-backend.md` | 原版代理与后端共用数据库、后端命令和数据查询通道 |
| `docs/database.md`、`database/DatabaseManager.java` | schema 7、绑定 / 背包 / 累计在线时长和迁移约束 |
| `docs/api.md`、`modules/api/` | 异步 API、无 QQ 白名单、数据提供器和原生图片能力 |
| 各平台 `PlayerLoginListener`、Spigot `SchedulerAdapter` | 登录异步等待、可信身份与 Folia 线程要求 |
| `docs/image-templates.md`、`modules/renderer/` | Java2D、高级模板、发布快照、编辑器和按需加载机制 |
| `docs/placeholders.md`、Spigot `ShitBotExpansion` | PAPI 查询和同步变量提供是两个方向 |
| `docs/updating.md`、`update/UpdateChecker.java` | 签名校验、平台构件校验与正常重启生效 |
| `config-templates/bstats.yml`、平台入口 | 普通版已有平台统计，以及 Ultra 需要独立 ID |

保留普通版中已经合理的业务边界、异步结果、有限队列、平台隔离、配置片段和不可变快照；不照搬它因“所有业务都在 JAR”而产生的共享数据库部署要求。

## 2. 参考项目与具体借鉴方式

| 官方项目 / 资料 | 已确认事实 | Ultra 采用的做法 |
| --- | --- | --- |
| [Go 模块组织指南](https://go.dev/doc/modules/layout) | 官方介绍 `cmd`、`internal` 与可导入包的组织方式 | Core 实现放 internal，窄 runtime 包供独立 CLI 仓库调用 |
| [Go embed](https://pkg.go.dev/embed) | 构建时嵌入模块内资源，有明确路径限制 | WebUI 构建输出属于 Core 模块，CLI 链接后无需 Node.js 运行环境 |
| [Cobra](https://cobra.dev/) | 提供命令树、帮助、参数和 Shell 补全；官方列有成熟使用项目 | CLI 按资源组织子命令，统一中文帮助和机器输出 |
| [frp](https://github.com/fatedier/frp) | 目录包含 cmd、client、server、pkg、web 等职责，具备管理界面 | 学习薄入口、明确网络组件边界及可选管理 UI，不照搬全部目录 |
| [Caddy 配置 API](https://caddyserver.com/docs/api#concurrent-config-changes) | 使用 ETag / If-Match 处理配置并发修改 | 多管理入口使用 revision，Core 协调在线持久化与生效 |
| [egui / eframe](https://github.com/emilk/egui) | 提供原生后端，采用自绘界面；可把耗时工作放到后台 | Rust 管理窗口与任务分离，不称为 Windows 原生控件 |
| [egui 中文输入讨论](https://github.com/emilk/egui/issues/8720) | 仓库讨论涉及字体 fallback 与输入法问题；不是兼容性保证 | 中文输入法、DPI、中文路径和字体许可列为维护者之后确认的项目 |
| [Tauri 架构](https://v2.tauri.app/concept/architecture/) | Rust 层配合 WebView 中的 HTML 页面 | 不采用为本次默认桌面方案，以符合独立桌面界面的要求 |
| [Slint 许可](https://github.com/slint-ui/slint/blob/master/LICENSE.md) | 有不同许可路线 | 作为备选前单独评估具体许可，不直接当作 MIT 依赖 |
| [EasyBot 官方简介](https://docs.inectar.cn/docs/easybot/intro/)、[Bridge](https://github.com/easybot-team/easybot-bridge) | Minecraft 项目具有主程序和服务端通信协议边界 | 参考中心程序 + 游戏适配器的形态，自行公开 Ultra 协议和实现 |
| [EasyBot 扩展说明](https://docs.inectar.cn/docs/easybot/develop/extension/) | 主程序与游戏侧存在扩展协作 | 预留版本化数据提供器能力，第一版不急于做扩展市场 |
| [SnowLuma](https://github.com/SnowLuma/SnowLuma)、[开发指南](https://snowluma.github.io/en/docs/guide/developer) | 有 OneBot 实现、独立模块边界及 WebUI | 推荐为新用户接入选择，Core 依赖协议而非绑定私有实现 |
| [LLBot](https://github.com/LLOneBot/LuckyLilliaBot) | 官方仓库说明支持 OneBot 11 等协议 | 保留已有可用部署的兼容选项；停止新注册的信息来自维护者本次说明 |

对于 EasyBot，只参考已公开的部署形态与协议分工；本规划不对其全部源码的开放程度作未核实判断。Ultra 的“全开源”约束针对自己的实现、协议、构建资产与文档，不代表可以改变第三方服务的使用条件。

## 3. 统计、签名与发布依据

- [bStats 官方接入页](https://bstats.org/add-plugin)：按平台使用对应集成；本次未见 Nukkit 的官方接入项，不冒用其他平台身份。
- [bStats FAQ](https://bstats.org/faq)：统计和服主关闭方式的说明入口。
- [bStats 使用条款](https://bstats.org/terms-of-use)：接入官方服务时遵循 Metrics 完整性与 opt-out 要求，特别注意普通版打包裁剪规则不能直接复制。
- [bStats 隐私说明](https://bstats.org/privacy-policy)：了解官方收集与请求元数据处理，不作“绝对匿名”的扩大承诺。
- [GitHub 提交签名核验](https://docs.github.com/en/authentication/managing-commit-signature-verification/about-commit-signature-verification)：签名提交与 GitHub Verified 的关联，本地签名结果和平台核验状态分别记录。

参考项目用于借鉴职责、接口和命名方法。若后续实际复用代码或资产，应保留原始许可与声明；当前规划不把任何参考项目的大段实现复制进 Ultra。
